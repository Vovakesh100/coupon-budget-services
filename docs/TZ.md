# ТЗ: coupon-budget-service

## Цель
HTTP-сервис, который выпускает купоны под бюджет рекламной кампании. Купон можно погасить только пока есть бюджет, а параллельные запросы не приводят к перерасходу. Учебный портфолио-проект (demo), не клиентская работа.

## Пользователь
Внешняя система (например, интернет-магазин), которая вызывает API. Пользовательских аккаунтов в MVP нет.

## Вход и выход
- `POST /campaigns`: создание кампании с бюджетом в micro (целое число).
- `POST /campaigns/{id}/coupons`: выпуск купона под кампанию.
- `POST /coupons/{id}/redeem` с заголовком `Idempotency-Key`: погашение купона, списание с бюджета.
- `GET /campaigns/{id}/budget`: текущее состояние бюджета.

## MVP
1. Создание кампании с бюджетом и сроком действия.
2. Выпуск купона с номиналом в micro.
3. Погашение купона: атомарно, идемпотентно по `Idempotency-Key`.
4. Состояние бюджета: выделено, списано, остаток.
5. Лимиты и сроки берутся из версионированного файла настроек.

## Не делаем
Аккаунты пользователей, оплату, веб-интерфейс, Redis Cluster, аналитику.

## Критерии приёмки
1. Property-тест (Hypothesis): `spent <= budget` выполняется после любой последовательности операций.
2. Повторный запрос с тем же `Idempotency-Key` не списывает деньги дважды (тест).
3. N параллельных погашений не превышают бюджет (интеграционный тест с Redis).
4. Суммы хранятся и передаются только как целые числа micro, без `float` (проверка тестами и типами).
5. Лимиты и сроки читаются из файла настроек; тест подтверждает, что новая версия настроек применяется.
